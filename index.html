Gorilla XOR Floating-Point Encoding Mechanics

Because adjacent sensor readings vary smoothly, XORing successive double-precision IEEE 754 floats yields identical exponent bits and high-order mantissa bits, creating wide spans of leading and trailing zeros. The Gorilla encoder bit-packs these differences, condensing 64-bit values to an average of 11.2 bits per reading.

Database Internals & Architectural Mechanisms

Technical foundation detailing hypertable chunk routing, Gorilla bit-packing, continuous aggregate materialization, and execution plan diffs.

01

Temporal Hypertable Partitioning

PostgreSQL monolithic tables ingest all tuples into one shared heap with global B-Trees. As index size eclipses shared_buffers, leaf splits cause cache evictions and random I/O. TimescaleDB partitions time into discrete 1-day chunks. Writes target solely the active chunk, remaining pinned in L3/RAM cache.

Chunk Interval: 1 Day (172,800 tuples/chunk)
02

Gorilla Delta-of-Delta & XOR

Closed historical chunks transform into compressed columnar relations. 64-bit timestamps with regular 10s intervals yield constant first-order differences ($D = 10$), making second-order differences zero ($D' = 0$), encoded in a single bit. Float metrics are XORed with preceding values to eliminate redundant mantissa bits.

Achieved Ratio: 6.07:1 (83.53% reduction)
03

Continuous Aggregate Materialization

PostgreSQL executes analytical rollups via full-table parallel sequential scans and hash aggregates across 1,209,600 tuples. TimescaleDB Continuous Aggregates incrementally pre-materialize bucketed aggregations into internal hypertable tables, converting multi-megabyte disk scans into direct primary index seeks over 3,360 rows.

Speedup Factor: 43.22x (12.01 ms vs 518.90 ms)
